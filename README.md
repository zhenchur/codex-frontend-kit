# Codex frontend kit

Переносимый комплект рабочего процесса для фронтенда: 8 навыков GSAP, отдельные
навыки редактуры, рабочие правила, снимок настроек и безопасный установщик.
Комплект подготовлен 21 октября 2026 года для переноса на другую машину.

Репозиторий [codex-frontend-kit](https://github.com/zhenchur/codex-frontend-kit) —
приватный: для клонирования нужен GitHub-аккаунт с доступом к нему.
Связанный проект анимации: [rost-motion-lab](https://github.com/zhenchur/rost-motion-lab).
Комплект можно использовать и в других frontend-проектах.

## Быстрый запуск

Нужны Git, Node.js 22.12+ и установленный Codex. Войдите в GitHub на новой машине
через используемый Git-клиент. Дополнительных npm-зависимостей нет.

```sh
git clone https://github.com/zhenchur/codex-frontend-kit.git
cd codex-frontend-kit
```

Затем проверьте комплект, просмотрите план и выполните установку:

```sh
node scripts/verify.mjs
node scripts/install.mjs
node scripts/install.mjs --apply
```

Первая команда проверяет комплект. Вторая показывает план **без записи файлов**.
Третья устанавливает 8 GSAP-навыков в `~/.agents/skills`, глобальный AGENTS.md
(если его ещё нет) и отдельный профиль `~/.codex/frontend.config.toml`.
При заданном CODEX_HOME правила и профиль идут в эту папку; user skills остаются
в `~/.agents/skills`. Существующие отличающиеся файлы по умолчанию пропускаются.

Если на новой машине уже есть собственный AGENTS.md, сначала просмотрите план:

```sh
node scripts/install.mjs --merge-agents
node scripts/install.mjs --apply --merge-agents
```

Это добавит отдельный помеченный блок наших правил, сохранит остальной текст и
сделает резервную копию. Для обновления уже установленных отличающихся файлов
есть явный флаг `--replace-existing`; перед заменой тоже создаются копии.
Ни один вариант не заменяет базовый `config.toml` и не переносит авторизацию.

## Настройки модели

В исходном конфиге обнаружены `gpt-6-astra`, `ultra`, `priority`. Они сохранены
в `profile/config.safe.toml` и устанавливаются как **неактивный по умолчанию**
именованный профиль. Для CLI, поддерживающего отдельные файлы профилей:

```sh
codex --profile frontend
```

В desktop-приложении выберите эти параметры в настройках нужного чата либо
осознанно перенесите три ключа из profile/config.safe.toml в свой config.toml.
Проверьте, что модель, reasoning effort и tier доступны вашему аккаунту. Профиль
не обещает одинаковую доступность или стоимость на другой машине. [Формат профилей](https://learn.chatgpt.com/docs/config-file/config-advanced).

## Что входит

| Состав | Установка |
| --- | --- |
| gsap-core, gsap-frameworks, gsap-performance, gsap-plugins | по умолчанию |
| gsap-react, gsap-scrolltrigger, gsap-timeline, gsap-utils | по умолчанию |
| copy-editing, humanizer | с `--include-optional` |
| Рабочие frontend-правила `profile/AGENTS.md` | по умолчанию, без перезаписи существующего файла |
| Профиль модели | отдельный frontend.config.toml |
| Allow-правило `npm run dev` | только с `--include-command-rules` |
| Figma/GitHub/браузерные инструменты | переустановка и подключение отдельно по plugins.json |

Пример полного опционального набора:

```sh
node scripts/install.mjs --include-optional --include-command-rules
node scripts/install.mjs --apply --include-optional --include-command-rules
```

Установка allow-правила разрешает запуск соответствующего npm-скрипта без отдельного
подтверждения в тех режимах Codex, где применяются эти правила. Оно не требуется
для анимации и не устанавливается автоматически.

## Figma и другие подключения

На исходной машине установлен Figma 16.0.0. В новой установке найдите официальный
плагин Figma, установите/включите его и подключите аккаунт. Проверьте чтение целевой
ноды. Аналогично подключите GitHub и убедитесь, что доступен нужный репозиторий.
Инструменты браузера используйте из текущего Codex; внутренние бинарники, pipe и
пути node_repl со старой машины переносить не нужно.

`plugins.json` сохраняет идентификаторы, доступную версию и нужные навыки Figma.
Это manifest восстановления, он сам не устанавливает плагины и не предоставляет
доступ к внешним сервисам. Не дублируйте навыки Figma вручную поверх установленного
плагина: одинаковые имена могут отображаться дважды.

## Правила для проектов

Исходный глобальный AGENTS.md был пуст. В комплекте его точный снимок сохранён
отдельно, а frontend-соглашения заново оформлены в profile/AGENTS.md. Источник каждого
типа данных описан в [MACHINE-SNAPSHOT.md](docs/MACHINE-SNAPSHOT.md).

Для нового репозитория адаптируйте [шаблон project AGENTS.md](templates/project-AGENTS.md).
Укажите настоящие команды, зависимости, ассеты и ссылки на дизайн конкретного проекта.
После установки начните новый чат в проекте и попросите Codex перечислить активные
источники правил и навыки GSAP. Если существует AGENTS.override.md, он может иметь
приоритет над AGENTS.md. [Правила загрузки инструкций](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Проверки и резервные копии

```sh
npm run verify
npm test
```

Проверяются SHA-256 файлов комплекта, относительные Markdown-ссылки в навыках,
сигнатуры секретов, dry-run, повторная установка, пропуск конфликтов, merge и backup.
Тесты работают только в созданных временных папках и не меняют живой Codex-профиль.
Резервные копии установщика: `<CODEX_HOME>/frontend-kit-backups/<timestamp>/`.
Для проверки на произвольной папке используйте `--home <absolute-path>`; для
отдельного Codex home — `--codex-home <absolute-path>`.

Список исключённых данных: [EXCLUDED.md](docs/EXCLUDED.md). Формат хранения проверен
по [официальным источникам](docs/SOURCES.md). Установщик не меняет настройки текущей
машины до явного `--apply` и никогда не выдаёт инструкции за разрешения доступа.
