# React frontend workflow

Применяй для разработки React-интерфейсов, включая перенос макета, CSS/БЭМ,
анимацию и прокрутку. Не используй как основание переводить существующий проект
на другой фреймворк или добавлять движение в обычную правку текста.

## Контекст и реализация

- Прочитай локальный AGENTS.md, package.json, lockfile, точки входа, существующие компоненты и motion-модуль. Сохраняй выбранные версии, маршрутизацию и менеджер пакетов.
- Для нового React-фронтенда без иных требований используй TypeScript и Vite, обычные `.css` с БЭМ. GSAP нужен для согласованной сложной анимации, Lenis — для требуемой плавной прокрутки; не устанавливай их ради статичного блока.
- При Figma-входе реализуй точную ноду через доступный Figma design-to-code workflow. Сохраняй токены, ассеты, структуру и незатронутые взаимодействия; после реализации сравни макет и браузер.
- Компоненты и их файлы — PascalCase; переменные и функции — camelCase; хуки — `use` + PascalCase. Типизируй props и refs. Частые обновления анимации держи вне React state.

## CSS и структура

Используй `block__element--modifier`, а также отдельные формы `block`,
`block__element`, `block--modifier`. Модификатор дополняет базовый класс:

```tsx
<article className="product-card product-card--featured">
  <h2 className="product-card__title product-card__title--muted">Заголовок</h2>
</article>
```

Имена частей — kebab-case. Reset, токены и базовые правила остаются в глобальном
CSS, стили компонента — в соседнем CSS-файле с его БЭМ-префиксом. Используй текущие
CSS custom properties; избегай глобальных селекторов, задевающих чужие блоки.
В принятом CSS/БЭМ-стеке не добавляй Tailwind или CSS Modules без запроса.
Существующий иной подход сохраняй. Держи контент доступным с клавиатуры и без
необязательной анимации.

## Анимация и прокрутка

- Читай профильные `gsap-react`, `gsap-core` и, для scroll-анимации, `gsap-scrolltrigger`, когда они доступны. Не переписывай общий motion-модуль ради одной секции.
- Регистрируй GSAP-плагины в общем модуле. Используй `useGSAP` с container ref и scope; при пересоздании по зависимостям — `revertOnUpdate`. Отложенное создание GSAP-объектов оборачивай в `contextSafe`, а таймеры, события и асинхронные операции очищай отдельно. `contextSafe` не заменяет отмену позднего callback.
- Убирай только свои эффекты и ScrollTrigger; компонент не должен вызывать глобальный `killAll()` при размонтировании. Обрабатывай responsive/reduced-motion изменения с возвратом к доступному статичному состоянию.
- Для Lenis прочитай [интеграцию и lifecycle](references/lenis.md). У основного scroller один владелец; GSAP ticker передаёт секунды как миллисекунды, второй RAF не нужен. Сохраняй нативное touch-поведение и текущую систему навигации.
- Обновляй размеры и ScrollTrigger после изменения layout, загрузки нужных шрифтов/изображений или завершения перехода. Не делай refresh на каждом кадре.

## Проверка

Запусти существующие typecheck/lint/build и значимые проверки изменённого поведения.
В браузере проверь responsive layout, клавиатуру, reduced motion, повторный mount,
быструю смену маршрута и отсутствие дублированного скролла, если это затронуто.
Сохрани визуальное подтверждение; отдельно назови то, что проверить не удалось.
Перед передачей проверь установку по lockfile и сборку в чистой копии.
